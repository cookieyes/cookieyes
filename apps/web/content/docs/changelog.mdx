<ChangelogEntry
  version="v1.4.0"
  date="2026-08-17"
  title="Critical CSS, Geo-Detection and Script Presets"
  packages={[
    { name: "react", version: "0.5.0" },
    { name: "core", version: "0.4.0" },
    { name: "nextjs", version: "0.5.1" },
    { name: "cli", version: "0.3.1" },
  ]}
  major
>

<ChangelogGroup kind="Added">

- `@cookieyes/react/critical.css` — a ~1.6 KB paint-critical banner stylesheet to inline in `<head>` ahead of the full `styles.css`
- Optional region-based regulation (geo-detection) — `region: { detect, map, honorGpc, strictest }` config, `<CookieYesProvider region={…}>`, the `useRegion()` hook, and `regionFromHeaders()` for reading a visitor's region on the server
- Consent-gated third-party integrations — the new `@cookieyes/scripts` package (Segment, Meta Pixel, Google GA4/Ads/Tag Manager presets) and `<GoogleConsentMode />` for deny-by-default Consent Mode from first paint
- `readServerConsent()`, `<CookieYesProvider initialConsent={…}>` and `getServerConsent()` — a returning visitor's banner no longer flashes on load

</ChangelogGroup>

<ChangelogGroup kind="Changed">

- `@cookieyes/cli`'s scaffolded Next.js layout now links to the `getServerConsent()` setup so new projects avoid the flash from day one

</ChangelogGroup>

<ChangelogGroup kind="Fixed">

- `@cookieyes/nextjs@0.5.1` repoints its `@cookieyes/scripts` dependency — `@cookieyes/scripts@0.1.0` shipped with an unresolvable `workspace:*` reference, which made `npm install @cookieyes/nextjs@0.5.0` fail with `EUNSUPPORTEDPROTOCOL`
- A failing third-party tag (a throwing `dataLayer.push`, a blocked script injection) can no longer strand the consent banner on screen or stop the SDK from mounting at all

</ChangelogGroup>

<ChangelogGroup kind="Breaking">

- The `integrations` config key — built-in vendor stop-handlers like `{ vendor: "meta" }` — is renamed to `builtInIntegrations`, because `integrations` now takes the new script presets. Existing `integrations: [{ vendor: … }]` code stops working as written; move those entries to `builtInIntegrations`

</ChangelogGroup>

</ChangelogEntry>

<ChangelogEntry
  version="v1.3.0"
  date="2026-08-05"
  title="Consent Events, Live Language Switching and Stable Selectors"
  packages={[
    { name: "core", version: "0.3.0" },
    { name: "react", version: "0.4.0" },
    { name: "nextjs", version: "0.4.0" },
    { name: "cli", version: "0.3.0" },
  ]}
>

<ChangelogGroup kind="Added">

- A consent event API — `consentStore.on("save" | "change", listener, { category? })` (core) and the `useOnConsentChange()` hook (React/Next.js)
- `useLanguage()` — read the active language and its direction, switch it live with `setLanguage(tag)`, no reload — plus `i18n.loadLanguage(tag)` to load a language on demand
- `data-cy-part` / `data-cy-state` on every pre-built component, and the typed `CY_PART` / `CY_STATE` constants, for precise CSS targeting
- `asChild` on control primitives — render your own element with the SDK's behavior and `data-cy-part` wired onto it
- `npx @cookieyes/cli init` now prints a short GitHub star nudge before its summary

</ChangelogGroup>

<ChangelogGroup kind="Changed">

- The styled presets (`CookieBanner`, `CookiePreferences`, `CookieOptOut`) now accept `className` / `style`, merged onto their default look
- `useTranslations()` now re-renders when the language changes (previously fixed at setup)

</ChangelogGroup>

</ChangelogEntry>

<ChangelogEntry
  version="v1.2.0"
  date="2026-07-20"
  title="Configurable Categories, Google Consent Mode v2 and Reload-Free Revocation"
  packages={[
    { name: "core", version: "0.2.0" },
    { name: "react", version: "0.3.0" },
    { name: "nextjs", version: "0.3.0" },
    { name: "cli", version: "0.2.0" },
    { name: "translations", version: "0.2.0" },
  ]}
>

<ChangelogGroup kind="Added">

- Configurable consent categories — a custom taxonomy via `categories` (core) / `.categories([...])` (React builder), each with a stable `id`, an explicit `required` flag, and an optional `gcm` mapping
- Automatic Google Consent Mode v2 broadcast on load and on every consent change — GA4 and Google Tag Manager no longer need an `integrations` entry
- `mode: "cookie-only"`, the clearer replacement for `mode: "offline"` (which is now `@deprecated` and scheduled for removal)
- `integrations` + built-in stop handlers (`meta` cleanly, others reload-only) and `customStopHandlers`, so revoking consent stops tracking without a full page reload; the new `<ReloadNotice />` / `useReloadNotice()` prompt covers the vendors that still need one
- `initCookieYes(config)` as the one canonical setup function and `CookieYesConfig` as the one canonical config shape across `core`/`react`/`nextjs`

</ChangelogGroup>

<ChangelogGroup kind="Changed">

- `@cookieyes/react/styles.css` is now a real, directly-importable file instead of being auto-injected — required for the SDK to render under a strict `style-src` CSP
- `@cookieyes/cli` bumped its `@clack/prompts` dependency (1.5.0 → 1.7.0) — folded in from its own untagged-on-the-timeline Jul 27, 2026 patch release (`@cookieyes/cli@0.2.1`); no user-facing behavior change

</ChangelogGroup>

<ChangelogGroup kind="Fixed">

- Consent-gated scripts, embeds and the network blocker now react only to a **committed** decision (Accept All / Reject All / Save), not to an in-progress toggle in the still-open preferences dialog
- Keyboard/focus management and screen-reader labeling across the banner and both dialogs (focus trapping, dialog focus return, named toggle switches), now covered by automated `axe-core` tests

</ChangelogGroup>

</ChangelogEntry>
