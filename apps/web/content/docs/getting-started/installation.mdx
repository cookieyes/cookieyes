## When to use it

Read this if you are adding CookieYes to an app for the first time. If you would rather have the files written for you, run the CLI in [Quick start](/docs/getting-started/quick-start) instead — it detects your framework and layout and does the wiring.

You do **not** need this page to add a second package later. `@cookieyes/nextjs` already depends on `@cookieyes/react` and `@cookieyes/core`, so installing it pulls both in.

### Next.js (App Router or Pages Router)

```npm
npm install @cookieyes/nextjs
```

### React (Vite, CRA, Remix, any React app)

```npm
npm install @cookieyes/react
```

### Framework-agnostic / vanilla JS

```npm
npm install @cookieyes/core
```

Then import the stylesheet once, at your app root:

```tsx title="app/layout.tsx"
import "@cookieyes/react/styles.css";
```

<Callout type="warn">
  The stylesheet is **required**, and skipping it fails silently: no error, no console warning, no build failure. The banner and dialogs still render — just as unstyled text with no layout.

  Import it **once, at your app root**, not inside a route or a component that might not mount first. `Banner.Root` and `RecallButton` portal into `<body>` (via `useBodyPortalRoot`), so the stylesheet must already be present before that portal paints — a root-level import is the only placement guaranteed to run regardless of which route rendered first.

  **Exception:** if you're building your own UI entirely on the headless `Banner.*` / `Preferences.*` / `OptOut.*` primitives with your own CSS, you don't need this import. Primitives carry `data-cy-part` and behavior only (`data-cy-state` is set by the presets, not the primitives — if you build on primitives you set it yourself) — the `cy-*` classes this sheet styles are applied by the presets (`CookieBanner`, `CookiePreferences`, `RecallButton`), not by the primitives themselves.
</Callout>

## Behaviour and trade-offs

### Which package for a Next.js app?

Install `@cookieyes/nextjs`, not `@cookieyes/react`. It mirrors the entire `react` surface, so nothing is lost, and it adds `getServerConsent()` on the `./server` subpath. Without that, a returning visitor sees the banner render on the server and vanish after hydration. See [Rendering & selector contract](/docs/rendering-and-selector-contract).

### `styles.css` vs `critical.css`

| Import | Contents | Size | When |
| --- | --- | --- | --- |
| `@cookieyes/react/styles.css` | Banner, preferences dialog, opt-out, toggles, recall widget, reload notice | ~17 KB raw / ~3.7 KB gzipped | **Always.** Import once per app |
| `@cookieyes/react/critical.css` | Only the rules needed to paint the banner | ~1.6 KB gzipped | Optional. Inline in `<head>` to keep the full sheet off the critical path |

`critical.css` is a **supplement, never a replacement**. Every rule in it is byte-identical to the same rule in `styles.css` (a test enforces this), so the two can never disagree. But if you ship only `critical.css`, the preferences dialog is unstyled the moment a visitor opens it.

Most apps do not need it: an app-root `import` normally puts `styles.css` in the critical path already.

### Prerequisites & framework support

| Requirement | Minimum |
| --- | --- |
| Node.js | ≥20 |
| React | ≥18 |
| Next.js | ≥14 — **both** App Router and Pages Router are supported |

| Framework | Supported | Package |
| --- | --- | --- |
| Next.js (App Router or Pages Router) | Yes | `@cookieyes/nextjs` |
| React (Vite, CRA, Remix, any React app) | Yes | `@cookieyes/react` |
| Vanilla JS / no framework | Yes | `@cookieyes/core` |
| Vue, Svelte, Angular, Solid | **No** — no adapter exists today | — |

**Time estimate (manual route):** typically 5–10 minutes — install the package, write the
consent-manager file, import the stylesheet, and wire it into your layout. If you'd rather skip
the manual wiring, the CLI in [Quick start](/docs/getting-started/quick-start) does it for you in
about a minute.

## Complete example

```tsx title="app/layout.tsx"
import { CookieYesProvider } from "@cookieyes/nextjs";
import { getServerConsent } from "@cookieyes/nextjs/server";
import "@cookieyes/react/styles.css";
import { CookieYesRoot } from "./cookieyes";

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const initialConsent = await getServerConsent({ regulation: "GDPR" });

  return (
    <html lang="en">
      <body>
        <CookieYesProvider regulation="GDPR" initialConsent={initialConsent}>
          {children}
          <CookieYesRoot />
        </CookieYesProvider>
      </body>
    </html>
  );
}
```

```tsx title="app/cookieyes.tsx"
"use client";

import { CookieBanner, CookiePreferences, RecallButton, initCookieYes } from "@cookieyes/nextjs";

initCookieYes({ mode: "cookie-only", regulation: "GDPR" });

export function CookieYesRoot() {
  return (
    <>
      <CookieBanner />
      <CookiePreferences />
      <RecallButton />
    </>
  );
}
```

## Common mistakes

**The banner renders as unstyled text.**
You did not import the stylesheet. This fails silently — no error, no console warning, no build failure. Add `import "@cookieyes/react/styles.css";` at your app root. Note the import path is `@cookieyes/react/styles.css` even in a Next.js app that installed `@cookieyes/nextjs` — the sheet lives in the `react` package.

**Nothing renders — no banner, no error anywhere.**
`initCookieYes()` has not run by the time a component rendered. This fails silently rather than loudly: every hook and every styled component reads the runtime through a non-throwing accessor, so a missing runtime never crashes the render or logs anything — it just produces nothing. The call must live in a module marked `"use client"` that is actually imported on the path to your components, and the components themselves must be in a `"use client"` file too. See [Quick start](/docs/getting-started/quick-start). You will only see a thrown error — `Error: [cookieyes] No runtime is registered. Call initCookieYes(...) in a 'use client' module before using hooks or components.` — from code that calls `getCookieYes()` or `useConsentRuntime()` directly.

**`You're importing a component that needs "use client"`** (Next.js App Router)
You called `initCookieYes()` in a Server Component. Move it into a `"use client"` module, as in the example above.

**The preferences dialog is unstyled but the banner looks right.**
You inlined `critical.css` and skipped `styles.css`. Load both.

## Across the SDK

The `CookieYesConfig` object is identical in `core`, `react`, and `nextjs` — a config is copy-pasteable between them with zero edits. `@cookieyes/nextjs` re-exports the whole `@cookieyes/react` surface, so imports can be switched by changing only the module specifier.
