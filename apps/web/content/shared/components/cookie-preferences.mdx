## What it does

Opens when a visitor clicks **Customise** on the banner, or the recall button. It lists your categories with a switch each; the required category shows "Always active" instead of a switch. Nothing is saved until the visitor presses **Save**, **Accept All** or **Reject All**.

You already render it if you followed [Installation](/docs/getting-started/installation). Without it, Customise does nothing.

## Open it from your own button

A "Cookie settings" link in your footer is the usual place:

<Framework when="nextjs react">

```tsx title="app/cookie-settings-link.tsx"
"use client";

import { useConsentActions } from "@cookieyes/react";

export function CookieSettingsLink() {
  const { showPreferences } = useConsentActions();
  return (
    <button type="button" onClick={showPreferences}>
      Cookie settings
    </button>
  );
}
```

</Framework>

<Framework when="vue">

```vue title="src/components/CookieSettingsLink.vue"

import { useConsentActions } from "@cookieyes/vue";

const { showPreferences } = useConsentActions();

<template>
  <button type="button" @click="showPreferences">Cookie settings</button>
```

</Framework>

## Restyle it

<Framework when="nextjs react">

It accepts `className` and `style` like any element; they are added to the dialog's own styling. For one part, use its `data-cy-part` in your CSS:

</Framework>

<Framework when="astro">

It accepts `class`, which lands on the dialog card and is added to its own styling. To restyle one part, pass `classNames`, keyed by part name in camelCase (`overlay`, `root`, `title`, `close`, `intro`, `category`, `categoryLabel`, `categoryDescription`, `toggle`, `acceptAll`, `rejectAll`, `save`, `branding`). There is no `style` or `styles` prop. Or use its `data-cy-part` in your CSS:

</Framework>

<Framework when="vue nuxt svelte sveltekit">

It accepts `class` and `style` like any element; they land on the dialog card and are added to its own styling. To restyle one part, pass `classNames` or `styles`, keyed by part name in camelCase (`overlay`, `root`, `title`, `close`, `intro`, `category`, `categoryLabel`, `categoryDescription`, `toggle`, `acceptAll`, `rejectAll`, `save`, `branding`). Or use its `data-cy-part` in your CSS:

</Framework>

```css title="app/consent.css"
[data-cy-part="dialog"] {
  max-width: 40rem;
}
```

The parts are `overlay`, `dialog`, `title`, `close`, `intro`, `category`, `category-label`, `category-description`, `toggle`, `accept-all`, `reject-all`, `save` and `branding`.

## Changing categories re-prompts every returning visitor

Saved choices are tied to your category list. If you add or remove a category, rename an `id`, or change which one is `required`, every returning visitor sees the banner again and chooses afresh. Changing a label or description does not. Decide your category ids early; change the wording as often as you like.

## Common mistakes

**Customise does nothing.**
`<CookiePreferences />` is not rendered.

<Framework when="astro">

In development, the browser console says so once: `The preferences dialog was opened, but <CookiePreferences /> is not in <CookieYesRoot /> on this page.` It happens when a default slot of `<CookieYesRoot>` leaves it out.

</Framework>

**A category is missing.**
Your `categories` list was rejected and the built-in five are shown instead. The console says why. See [Configuration](/docs/getting-started/configuration).

**The Necessary switch cannot be turned off.**
Correct. It is `required: true`, and required cookies need no consent.
