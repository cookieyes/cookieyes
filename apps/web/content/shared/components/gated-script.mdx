## What it does

Registers a script and loads it only once its category is granted. Until then, nothing is downloaded and nothing runs. It renders nothing itself.

Use it for any tag you can reference in code: analytics, ad pixels, chat widgets. If CookieYes has an [integration](/docs/integrations) for your tool (Google Analytics, Google Tag Manager, Meta Pixel, PostHog, Segment, Microsoft Clarity, Ahrefs Web Analytics, Hotjar, Matomo, Microsoft Advertising, TikTok Pixel, Mixpanel), use that instead: it also handles what happens when consent is withdrawn.

import { CookieYesRoot, GatedScript } from "@cookieyes/astro/components";
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
  </head>
  <body>
    <CookieYesRoot />

The component renders only a marker, so the script is not in the HTML and nothing is downloaded before consent. To run code after the script loads, use [`onConsentChange()`](/docs/client-functions#onconsentchange) or `src/cookieyes.client.ts`: a prop cannot hold a function across the server boundary, so there is no `onLoad`.

</Framework>

## Which category

Pick the category that describes what the tool does with visitor data, and make sure it exists in your `categories` list:

| Tool | Category |
| --- | --- |
| Analytics, heatmaps, session recording | `analytics` |
| Ad and retargeting pixels | `advertisement` |
| Chat widgets and other visitor preferences | `functional` |

## Good to know

Once a script has loaded, withdrawing consent does not unload it in the current page: it has already run. It is not loaded again on the next page load.

## Common mistakes

**The script never loads, even after accepting.**
The `category` is not in your `categories` list, so it can never be granted.

**The script loads before consent.**
Something else loads it too: a plain `<script>` tag, your framework's script component, or an import. Remove that.

**Two scripts, only one loads.**
They share an `id`. Give each one its own.
