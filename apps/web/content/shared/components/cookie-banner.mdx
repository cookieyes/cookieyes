## What it does

Shows on the first visit and stays until the visitor chooses. Under GDPR it offers **Accept All**, **Reject All** and **Customise**; under CCPA it offers **Do Not Sell**. After a choice it disappears and does not come back in that browser. Its close button hides it for this page view without saving anything; it returns on the next page load, and the recall button appears meanwhile. It shows and hides itself; you only render it.

You already render it if you followed [Installation](/docs/getting-started/installation). Try it in the [Playground](/playground).

<Framework when="nuxt">

In Nuxt, `<CookieYesRoot />` renders it for you. To render it yourself, for example to pass it props, list the components inside `<CookieYesRoot>`: its slot replaces the default contents, so keep the others you need.

```vue title="app/app.vue"
<template>
  <CookieYesRoot>
    <CookieBanner class="my-banner" />
    <CookiePreferences />
    <RecallButton />
  </CookieYesRoot>
  <NuxtPage />
</template>
```

</Framework>

<Framework when="sveltekit">

In SvelteKit, `<CookieYesRoot>` renders it for you. To render it yourself, for example to pass it props, give `<CookieYesRoot>` a `ui` snippet: it replaces the stock banner, dialogs and recall button, so keep the others you need.

```svelte title="src/routes/+layout.svelte"
<script lang="ts">
  import {
    CookieBanner,
    CookiePreferences,
    CookieYesRoot,
    RecallButton,
  } from "@cookieyes/sveltekit";
  import { config } from "../lib/cookieyes";

  let { data, children } = $props();
</script>

<CookieYesRoot {config} state={data.consent}>
  {#snippet ui()}
    <CookieBanner class="my-banner" />
    <CookiePreferences />
    <RecallButton />
  {/snippet}
  {@render children()}
</CookieYesRoot>
```

</Framework>

## Change what it shows

<Framework when="nextjs react">

Nothing on the banner is set through props. Everything comes from `initCookieYes()`, so the banner, the dialogs and the recall button always match.

</Framework>

<Framework when="vue">

Nothing on the banner is set through props. Everything comes from the config you pass to `app.use(CookieYes, config)`, so the banner, the dialogs and the recall button always match.

</Framework>

<Framework when="nuxt">

Nothing on the banner is set through props. Everything comes from the `cookieyes` key in `nuxt.config.ts` and `app/app.config.ts`, so the banner, the dialogs and the recall button always match.

</Framework>

<Framework when="svelte">

Nothing on the banner is set through props. Everything comes from the `config` you pass to `<CookieYesProvider>`, so the banner, the dialogs and the recall button always match.

</Framework>

<Framework when="sveltekit">

Nothing on the banner is set through props. Everything comes from the config in `src/lib/cookieyes.ts`, so the banner, the dialogs and the recall button always match.

</Framework>

| To change | Set |
| --- | --- |
| The wording, in any language | `i18n`, see [Translations](/docs/translations) |
| Colours, corner radius, font | `theme`, see [Theme tokens](/docs/styling/theme-tokens) |
| Which buttons appear | `regulation`: `"GDPR"` shows Accept / Reject / Customise, `"CCPA"` shows Do Not Sell |
| The categories behind Customise | `categories`, see [Configuration](/docs/getting-started/configuration) |

## Restyle it

<Framework when="nextjs react">

It accepts `className` and `style` like any element; they are added to the banner's own styling, not replacing it. For one part of the banner, use its `data-cy-part` in your CSS:

</Framework>

<Framework when="vue nuxt">

It accepts `class` and `style` like any element; they land on the banner card and are added to its own styling, not replacing it. To restyle one part, pass `classNames` or `styles`, keyed by part name in camelCase (`root`, `title`, `description`, `actions`, `acceptAll`, `rejectAll`, `customise`, `doNotSell`, `close`, `branding`), for example `:class-names="{ acceptAll: 'my-accept' }"`. Or use its `data-cy-part` in your CSS:

</Framework>

<Framework when="svelte sveltekit">

It accepts `class` and `style` like any element; they land on the banner card and are added to its own styling, not replacing it. To restyle one part, pass `classNames` or `styles`, keyed by part name in camelCase (`root`, `title`, `description`, `actions`, `acceptAll`, `rejectAll`, `customise`, `doNotSell`, `close`, `branding`), for example `classNames={{ acceptAll: "my-accept" }}`. `styles` takes camelCase property names or custom properties. Or use its `data-cy-part` in your CSS:

</Framework>

```css title="app/consent.css"
[data-cy-part="banner"] {
  max-width: 32rem;
}

[data-cy-part="accept-all"] {
  font-weight: 600;
}
```

The parts are `banner`, `title`, `description`, `actions`, `accept-all`, `reject-all`, `customise`, `do-not-sell`, `close` and `branding`. For your own markup, not only your own styles, use the [Banner primitives](/docs/headless/banner).

## Common mistakes

**The banner never appears.**
You already chose in this browser. Delete the `cookieyes-consent` cookie and reload.

<Framework when="nextjs react vue svelte">

**The banner is unstyled text.**
The stylesheet import is missing. See [Installation](/docs/getting-started/installation).

</Framework>

<Framework when="sveltekit">

**The banner is unstyled text.**
The stylesheet route is missing. Add `src/routes/cookieyes/styles.css/+server.ts`, as in [Installation](/docs/getting-started/installation).

</Framework>

**Do Not Sell does nothing.**
`<CookieOptOut />` is not rendered.
