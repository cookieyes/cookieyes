<Framework when="astro">

```npm
npm install @cookieyes/astro
```

This is the only package you install. `astro` is a peer dependency, so the copy your app already has is the one used. `npx astro add @cookieyes/astro` installs it and adds it to `integrations` in one go.

</Framework>

<Framework when="core">

```npm
npm install @cookieyes/core
```

`@cookieyes/core` is the engine alone: it stores and applies consent, runs integrations and blocks requests, and draws nothing. The banner is yours to build, on [the consent store](/docs/store/using-the-store).

For a ready-made banner in Svelte, Angular, Solid or any other framework without a CookieYes adapter, use [`@cookieyes/vanilla`](/docs/getting-started/vanilla) instead. Vue has its own adapter, `@cookieyes/vue`: use that, not `@cookieyes/core`.

</Framework>

## 2. Create the consent manager

One file: the configuration, the stylesheet, and the three components.

<Framework when="nextjs">

```tsx title="app/consent-manager.tsx" group="setup"
"use client";

import { CookieBanner, CookiePreferences, RecallButton, initCookieYes } from "@cookieyes/react";
import "@cookieyes/react/styles.css";

initCookieYes({
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
});

export function CookieYesRoot() {
  return (
    <>
      <CookieBanner />
      <CookiePreferences />
      <RecallButton />
    </>
  );
}
```

The file must start with `"use client"`: the banner runs in the browser, and so does `initCookieYes()`.

</Framework>

<Framework when="react">

```tsx title="src/consent-manager.tsx" group="setup"
import { CookieBanner, CookiePreferences, RecallButton, initCookieYes } from "@cookieyes/react";
import "@cookieyes/react/styles.css";

initCookieYes({
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
});

export function CookieYesRoot() {
  return (
    <>
      <CookieBanner />
      <CookiePreferences />
      <RecallButton />
    </>
  );
}
```

</Framework>

The stylesheet import is required. The components ship no inline styling, so without it they render as plain text, with no error to tell you why.

## 3. Render it once

<Framework when="nextjs">

```tsx title="app/layout.tsx" group="setup"
import { CookieYesRoot } from "./consent-manager";

export default function RootLayout({ children }: { children: React.ReactNode }) {
```

</Framework>

<Framework when="react">

## 2. Add the plugin

One file: the configuration and the stylesheet.

```ts title="src/consent-manager.ts" group="setup"
import type { App } from "vue";
import { CookieYes, type CookieYesConfig } from "@cookieyes/vue";
import "@cookieyes/vue/styles.css";

const config: CookieYesConfig = {
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
};

export function setupConsent(app: App): void {
  app.use(CookieYes, config);
}
```

`app.use(CookieYes, config)` takes the same configuration as `initCookieYes()` in the other packages, so a configuration copies across unchanged.

The stylesheet import is required. The components ship no inline styling, so without it they render as plain text, with no error to tell you why.

## 3. Render it once

Call `setupConsent` before the app mounts:

```ts title="src/main.ts" group="setup"
import { createApp } from "vue";
import App from "./App.vue";
import { setupConsent } from "./consent-manager";

const app = createApp(App);
setupConsent(app);
app.mount("#app");
```

A component renders the banner, the preferences dialog and the recall button:

```vue title="src/components/CookieYesRoot.vue" group="setup"
<script setup lang="ts">
import { CookieBanner, CookiePreferences, RecallButton } from "@cookieyes/vue";
</script>

<template>
  <CookieBanner />
  <CookiePreferences />
  <RecallButton />
</template>
```

Put it before your page content, so the banner is early in the DOM: screen readers announce it first, and it paints before the rest of the page.

```vue title="src/App.vue" group="setup"
<script setup lang="ts">
import CookieYesRoot from "./components/CookieYesRoot.vue";
</script>

<template>
  <CookieYesRoot />
  <h1>Your app</h1>
</template>
```

Done. Reload the page and the banner appears. If it does not, see [Common mistakes](#common-mistakes).

## 2. Add the module

```ts title="nuxt.config.ts" group="setup"
export default defineNuxtConfig({
  modules: ["@cookieyes/nuxt"],
  cookieyes: {
    mode: "cookie-only", // the default: no backend needed
    regulation: "GDPR", // "GDPR" | "CCPA"
  },
});
```

The `cookieyes` key takes the same configuration as `initCookieYes()` in the other packages, so a configuration copies across unchanged. Options that hold functions, such as integrations and callbacks, go in `app/app.config.ts` instead; see [Configuration](/docs/getting-started/configuration).

There is no stylesheet to import. The module puts the banner's critical CSS in the server HTML and serves the full stylesheet itself.

## 3. Render it once

```vue title="app/app.vue" group="setup"
<template>
  <CookieYesRoot />
  <NuxtPage />
</template>
```

`<CookieYesRoot />` renders the banner, the preferences dialog and the recall button, plus the opt-out dialog when a CCPA regulation can apply. Nuxt imports it for you. Keep it in `app.vue`, outside `<NuxtPage />`, so it stays mounted across navigation, and before your page content, so the banner is early in the DOM: screen readers announce it first, and it paints before the rest of the page.

Done. Reload the page and the banner appears. It is already in the server HTML, and a visitor who has chosen before gets no banner at all. If it does not appear, see [Common mistakes](#common-mistakes).

</Framework>

## 2. Write the configuration

Put the configuration in a module of its own, so every render reuses one object instead of starting a new runtime:

```ts title="src/lib/cookieyes.ts" group="setup"
import type { CookieYesConfig } from "@cookieyes/svelte";

export const config: CookieYesConfig = {
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
};
```

`<CookieYesProvider>` takes the same configuration as `initCookieYes()` in the other packages, so a configuration copies across unchanged.

## 3. Render it once

A component starts the SDK and renders the banner, the preferences dialog and the recall button. Everything inside it can use the hooks:

```svelte title="src/lib/CookieYesRoot.svelte" group="setup"
<script lang="ts">
  import type { Snippet } from "svelte";
  import {
    CookieBanner,
    CookiePreferences,
    CookieYesProvider,
    RecallButton,
  } from "@cookieyes/svelte";
  import { config } from "./cookieyes";

  let { children }: { children?: Snippet } = $props();
</script>

<CookieYesProvider {config}>
  <CookieBanner />
  <CookiePreferences />
  <RecallButton />
  {@render children?.()}
</CookieYesProvider>
```

Wrap your app in it once. Keep the banner before your page content, so it is early in the DOM: screen readers announce it first, and it paints before the rest of the page.

```svelte title="src/App.svelte" group="setup"
<script lang="ts">
  import CookieYesRoot from "./lib/CookieYesRoot.svelte";
</script>

<CookieYesRoot>
  <h1>Your app</h1>
</CookieYesRoot>
```

Load the stylesheet where the app starts:

```ts title="src/main.ts" group="setup"
import "@cookieyes/svelte/styles.css";
import { mount } from "svelte";
import App from "./App.svelte";

const target = document.getElementById("app");
if (target) mount(App, { target });
```

The stylesheet import is required. The components ship no inline styling, so without it they render as plain text, with no error to tell you why.

Done. Reload the page and the banner appears. If it does not, see [Common mistakes](#common-mistakes).

</Framework>

## 2. Add the handle

Put the configuration in a module of its own. The server and the browser both import it, so they run the same options:

```ts title="src/lib/cookieyes.ts" group="setup"
import type { CookieYesConfig } from "@cookieyes/sveltekit";

export const config: CookieYesConfig = {
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
};
```

`cookieyesHandle` and `<CookieYesRoot>` take the same configuration as `initCookieYes()` in the other packages, so a configuration copies across unchanged.

Add the handle, which reads each request once:

```ts title="src/hooks.server.ts" group="setup"
import { cookieyesHandle } from "@cookieyes/sveltekit";
import { config } from "./lib/cookieyes";

export const handle = cookieyesHandle(config);
```

Serve the stylesheet the handle links to:

```ts title="src/routes/cookieyes/styles.css/+server.ts" group="setup"
export { GET } from "@cookieyes/sveltekit/styles-route";
```

And let TypeScript know about `event.locals.cookieyes`:

```ts title="src/app.d.ts" group="setup"
/// <reference types="@cookieyes/sveltekit" />
export {};
```

There is no stylesheet to import. The handle writes the banner's critical CSS into the head of every page and loads the full stylesheet from the route above.

## 3. Render it once

Pass what the handle read to the page from the root layout's server `load`:

```ts title="src/routes/+layout.server.ts" group="setup"
import { loadConsent } from "@cookieyes/sveltekit";

export const load = loadConsent;
```

Render `<CookieYesRoot>` in the root layout, with the page inside it:

```svelte title="src/routes/+layout.svelte" group="setup"
<script lang="ts">
  import { CookieYesRoot } from "@cookieyes/sveltekit";
  import { config } from "../lib/cookieyes";

  let { data, children } = $props();
</script>

<CookieYesRoot {config} state={data.consent}>
  {@render children()}
</CookieYesRoot>
```

`<CookieYesRoot>` renders the banner, the preferences dialog and the recall button, plus the opt-out dialog when a CCPA regulation can apply, and then your page, inside the same provider, so the hooks work in every page and component. The root layout stays mounted across navigation, and the banner comes before your page content in the DOM: screen readers announce it first, and it paints before the rest of the page.

Done. Reload the page and the banner appears. It is already in the server HTML, and a visitor who has chosen before gets no banner at all. If it does not appear, see [Common mistakes](#common-mistakes).

</Framework>

## 2. Add the integration

```ts title="astro.config.ts" group="setup"
import cookieyes from "@cookieyes/astro";
import { defineConfig } from "astro/config";

export default defineConfig({
  integrations: [
    cookieyes({
      mode: "cookie-only", // the default: no backend needed
      regulation: "GDPR", // "GDPR" | "CCPA"
    }),
  ],
});
```

The examples use `astro.config.ts`; the same code works in `astro.config.mjs`. `cookieyes()` takes the same configuration as `initCookieYes()` in the other packages, so a configuration copies across unchanged. Options that hold functions, such as integrations and callbacks, go in `src/cookieyes.client.ts` instead; see [Configuration](/docs/getting-started/configuration).

There is no stylesheet to import. The integration puts the banner's critical CSS in the head of every page and links the full stylesheet from a route it adds.

## 3. Render it once

```astro title="src/layouts/Layout.astro" group="setup"
---
import { CookieYesRoot } from "@cookieyes/astro/components";
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
  </head>
  <body>
    <CookieYesRoot />
    <slot />
  </body>
</html>
```

`<CookieYesRoot />` renders the banner, the preferences dialog and the recall button, plus the opt-out dialog when a CCPA regulation can apply. Keep it first in the `<body>`, so the banner is early in the DOM: screen readers announce it first, and it paints before the rest of the page. Keep `<meta charset>` in the `<head>`: the integration adds its tags right after it.

```astro title="src/pages/index.astro" group="setup"
---
import Layout from "../layouts/Layout.astro";
---
<Layout>
  <h1>Your app</h1>
</Layout>
```

Done. Reload the page and the banner appears. On a static page it is in the HTML, hidden, and a small script in the head shows it before first paint to a visitor who has not chosen. If it does not appear, see [Common mistakes](#common-mistakes).

</Framework>

## 2. Initialise the runtime

```ts title="src/consent.ts"
import { initCookieYes } from "@cookieyes/core";

export const { consentStore, consentManager } = initCookieYes({
  mode: "cookie-only", // no backend needed
  regulation: "GDPR", // "GDPR" | "CCPA"
});
```

Done. `consentStore` tells you what to show and `consentManager` records what the visitor chose. [Build your own UI](/docs/store/build-your-own-ui) renders a banner from them in about 60 lines.

## Common mistakes

<Framework when="nextjs react">

**The banner renders as unstyled text.**
The stylesheet import is missing. Keep the `styles.css` import in `consent-manager.tsx`, where the example above has it.

**Nothing renders: no banner, no error anywhere.**
`initCookieYes()` never ran, because the file that calls it is not imported anywhere. Make sure `<CookieYesRoot />` is rendered, as in step 3. There is no error by design.

</Framework>

<Framework when="vue">

**The banner renders as unstyled text.**
The stylesheet import is missing. Keep the `@cookieyes/vue/styles.css` import in `consent-manager.ts`, where the example above has it.

**A CookieYes component or composable throws "could not find CookieYes".**
`app.use(CookieYes, config)` has not run on the app that renders it. Call `setupConsent(app)` before `app.mount()`, as in step 3, and call composables inside `setup()`.

**Nothing renders: no banner, no error anywhere.**
`<CookieYesRoot />` is not rendered by any component. Render it once, as in step 3.

</Framework>

<Framework when="nuxt">

**`Failed to resolve component: CookieYesRoot` in the console.**
`@cookieyes/nuxt` is missing from `modules` in `nuxt.config.ts`. Add it, as in step 2.

**Nothing renders: no banner, no error anywhere.**
`<CookieYesRoot />` is not in `app/app.vue`. Render it once, as in step 3.

**An integration or a callback never runs.**
It is in `nuxt.config.ts`, where options become runtime config, which is JSON and drops functions. Move it under `cookieyes` in `app/app.config.ts`. In development the module logs a warning naming the option.

</Framework>

<Framework when="svelte">

**The banner renders as unstyled text.**
The stylesheet import is missing. Keep the `@cookieyes/svelte/styles.css` import in `src/main.ts`, where the example above has it.

**A component or hook throws "could not find CookieYes".**
It is not inside `<CookieYesProvider>`, or a hook was called outside component initialisation, for example in an event handler. Render it inside `<CookieYesRoot>`, as in step 3, and call hooks at the top of a component's `<script>`.

**A warning that `<CookieYesProvider>` ran again with a different config.**
The config is written inline, so each render builds a new object and replaces the runtime. Import the one object from `src/lib/cookieyes.ts`, as in step 2.

</Framework>

<Framework when="sveltekit">

**`loadConsent() found no event.locals.cookieyes` in the server log.**
The handle is missing. Export `handle = cookieyesHandle(config)` from `src/hooks.server.ts`, as in step 2. If you have a handle of your own, combine the two with `sequence()` from `@sveltejs/kit/hooks`.

**`<CookieYesRoot> needs a config prop`.**
Pass the object from `src/lib/cookieyes.ts`: `<CookieYesRoot {config} state={data.consent}>`, as in step 3.

**The banner renders as unstyled text.**
The stylesheet route is missing, or is mounted somewhere other than `/cookieyes/styles.css`. Add `src/routes/cookieyes/styles.css/+server.ts`, as in step 2, or set `stylesHref` on the handle to where you mounted it.

**Your page renders, but the hooks throw "could not find CookieYes".**
The component is outside `<CookieYesRoot>`. Render the page through `{@render children()}` inside it, as in step 3.

</Framework>

<Framework when="astro">

**`[cookieyes] Add cookieyes() to integrations in astro.config.mjs.` in the server log.**
The integration is missing, so `<CookieYesRoot />` renders nothing. Add `cookieyes()` to `integrations`, as in step 2.

**Nothing renders: no banner, no error anywhere.**
`<CookieYesRoot />` is not in the layout of the page you are looking at. Render it once, as in step 3. In development the browser console says `<CookieYesRoot /> in your layout` when a CookieYes component is on a page without one.

**The banner renders as unstyled text.**
The stylesheet route is not reachable, or `stylesHref` points somewhere it is not served. The default is `/cookieyes/styles.css`.

**An integration or a callback never runs.**
It is in `astro.config.ts`, where options become JSON and functions are dropped. Move it to `src/cookieyes.client.ts`. In development the integration logs a warning naming the option.

</Framework>

<Framework when="nextjs">

**`You're importing a component that needs "use client"`**
`consent-manager.tsx` lost its `"use client"` line, or you called `initCookieYes()` directly in `layout.tsx`. Keep the call and the components in the client file.

**The banner appears for a second, then disappears, for a visitor who already chose.**
Expected by default: the server does not know the visitor's decision, so it renders the banner and the browser removes it. To fix it, read the decision on the server and pass it in. See [Runtime and server helpers](/docs/hooks/low-level-hooks#read-a-returning-visitors-consent-on-the-server).

</Framework>

<Framework when="core">

**Nothing appears on the page.**
Nothing is meant to. `@cookieyes/core` draws no UI; it decides what should show and records what the visitor chose. Render the banner yourself from `consentStore`, as in [Build your own UI](/docs/store/build-your-own-ui).

**`initCookieYes()` seems to run twice.**
The module that calls it is imported from two places under a bundler that duplicates it, or you call it inside a function. Each call replaces the runtime and logs a warning. Call it once, at module scope, and import the result.

</Framework>
