<Framework when="nextjs react core">

`initCookieYes(config)` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default.

```ts check="false"
initCookieYes({
  mode: "cookie-only",
  regulation: "GDPR",
  theme: { primaryColor: "#1863dc" },
});
```

</Framework>

<Framework when="vue">

`app.use(CookieYes, config)` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default. The config is the same `CookieYesConfig` that `initCookieYes()` takes in the other packages.

```ts title="src/consent-manager.ts"
import type { App } from "vue";
import { CookieYes } from "@cookieyes/vue";

export function setupConsent(app: App): void {
  app.use(CookieYes, {
    mode: "cookie-only",
    regulation: "GDPR",
    theme: { primaryColor: "#1863dc" },
  });
}
```

</Framework>

<Framework when="svelte">

The `config` you pass to `<CookieYesProvider>` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default. The config is the same `CookieYesConfig` that `initCookieYes()` takes in the other packages.

```ts title="src/lib/cookieyes.ts"
import type { CookieYesConfig } from "@cookieyes/svelte";

export const config: CookieYesConfig = {
  mode: "cookie-only",
  regulation: "GDPR",
  theme: { primaryColor: "#1863dc" },
};
```

The provider reads the config once, when it starts the runtime. Keep it in this module and import it, rather than writing it inline in a component.

</Framework>

<Framework when="sveltekit">

`src/lib/cookieyes.ts` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default. The config is the same `CookieYesConfig` that `initCookieYes()` takes in the other packages.

```ts title="src/lib/cookieyes.ts"
import type { CookieYesConfig } from "@cookieyes/sveltekit";

export const config: CookieYesConfig = {
  mode: "cookie-only",
  regulation: "GDPR",
  theme: { primaryColor: "#1863dc" },
};
```

`cookieyesHandle(config)` in `src/hooks.server.ts` and `<CookieYesRoot {config}>` in `src/routes/+layout.svelte` both import this object, so the server and the browser run the same options. The config never travels in `data`: SvelteKit serialises what a server `load` returns, so `loadConsent` hands over only what the server read, and options that hold functions, such as `integrations` and callbacks, come from this module on each side.

</Framework>

<Framework when="astro">

`cookieyes({ ... })` in `astro.config.ts` is where you configure CookieYes. It takes the same `CookieYesConfig` that `initCookieYes()` takes in the other packages. `mode` defaults to `"cookie-only"` here, so no option is required.

```ts title="astro.config.ts" group="config"
import cookieyes from "@cookieyes/astro";
import { defineConfig } from "astro/config";

export default defineConfig({
  integrations: [
    cookieyes({
      regulation: "GDPR",
      theme: { primaryColor: "#1863dc" },
    }),
  ],
});
```

Options that hold functions, such as `integrations`, `onConsentReady`, `onConsentUpdate` and `region.detect`, go in `src/cookieyes.client.ts` instead, as its default export. The config reaches the server and the browser as JSON, which drops functions; in development the integration warns, naming the option, when it finds one in the Astro config.

```ts title="src/cookieyes.client.ts" group="config"
import type { CookieYesConfig } from "@cookieyes/astro";

export default {
  onConsentUpdate: (state) => {
    console.log("Consent saved", state.categories);
  },
} satisfies Partial<CookieYesConfig>;
```

The integration finds `src/cookieyes.client.ts` (or `.js`) by itself and merges it over the config. The file wins for a key set in both, and one level of nesting is merged, so `i18n.messages` in one and `i18n.loadLanguage` in the other both apply. Arrays are replaced, not combined. Keep `categories` in the Astro config: the script in the head that decides whether a static page shows the banner reads them there.

</Framework>

<Framework when="nuxt">

The `cookieyes` key in `nuxt.config.ts` is where you configure CookieYes. It takes the same `CookieYesConfig` that `initCookieYes()` takes in the other packages. `mode` defaults to `"cookie-only"` here, so no option is required.

```ts title="nuxt.config.ts" group="config"
export default defineNuxtConfig({
  modules: ["@cookieyes/nuxt"],
  cookieyes: {
    regulation: "GDPR",
    theme: { primaryColor: "#1863dc" },
  },
});
```

Options that hold functions, such as `integrations`, `onConsentReady` and `onConsentUpdate`, go under the same key in `app/app.config.ts`. `nuxt.config.ts` becomes runtime config, which is JSON and drops functions; in development the module warns when it finds one there.

```ts title="app/app.config.ts" group="config"
export default defineAppConfig({
  cookieyes: {
    onConsentUpdate: (state) => {
      console.log("Consent saved", state.categories);
    },
  },
});
```

The module merges the two files. `app.config.ts` wins for a key set in both, and one level of nesting is merged, so `i18n.messages` in one file and `i18n.loadLanguage` in the other both apply. Arrays are replaced, not combined.

</Framework>

## Options

<Framework when="nuxt">

### Module options

Two options exist only in the Nuxt module, under `cookieyes` in `nuxt.config.ts`:

| Option | Default | What it does |
| --- | --- | --- |
| `stylesHref` | `"/cookieyes/styles.css"` | The path the module serves the full stylesheet from. |
| `googleConsentMode` | not set | `true`, or Consent Mode options, adds Google's deny-by-default snippet right after `<meta charset>`, before any Google tag. See [Google Consent Mode](/docs/integrations/google-consent-mode). |

</Framework>

<Framework when="astro">

### Integration options

Two options exist only in `cookieyes()`:

| Option | Default | What it does |
| --- | --- | --- |
| `stylesHref` | `"/cookieyes/styles.css"` | The path the full stylesheet is served from: a file in a static build, a compressed and cached response on a server. |
| `googleConsentMode` | not set | `true`, or Consent Mode options, adds Google's deny-by-default snippet right after `<meta charset>`, before any Google tag. See [Google Consent Mode](/docs/integrations/google-consent-mode). |

</Framework>

<Framework when="sveltekit">

### Handle options

Two options exist only in `cookieyesHandle`. Pass them next to the shared config:

```ts title="src/hooks.server.ts"
import { cookieyesHandle } from "@cookieyes/sveltekit";
import { config } from "./lib/cookieyes";

export const handle = cookieyesHandle({ ...config, googleConsentMode: true });
```

| Option | Default | What it does |
| --- | --- | --- |
| `stylesHref` | `"/cookieyes/styles.css"` | The path the stylesheet route is mounted at. The handle links the full stylesheet from there. |
| `googleConsentMode` | not set | `true`, or Consent Mode options, adds Google's deny-by-default snippet right after `<meta charset>`, before any Google tag. See [Google Consent Mode](/docs/integrations/google-consent-mode). |

The handle composes with your own: `export const handle = sequence(cookieyesHandle(config), yourHandle)`, with `sequence` from `@sveltejs/kit/hooks`. A `transformPageChunk` of yours still runs.

</Framework>

### `region`

<ConfigNestedTable path="region" />

<Framework when="nuxt">

Put `region.map` in `nuxt.config.ts`. On a page the server renders per request, the module reads the region from the Vercel or Cloudflare geo headers, and those headers are the only region source, for the banner and for the browser alike. A `region.detect` in `app/app.config.ts` is used only where the server reads nothing (`ssr: false`, `nuxt generate`, and routes with `swr`, `isr`, `cache` or `prerender` route rules), once the page has loaded.

</Framework>

<Framework when="astro">

Put `region.map` in `astro.config.ts`. On a page rendered on request (`prerender = false`), the integration reads the region from the Vercel (`x-vercel-ip-country`, `x-vercel-ip-country-region`) or Cloudflare (`cf-ipcountry`) geo headers, and those headers are the only region source, for the banner and for the browser alike. A `region.detect` in `src/cookieyes.client.ts` is used only where the server reads nothing, which is a prerendered page, once the page has loaded. Until then such a page shows the banner of the strictest regulation. The result of the request is `Astro.locals.cookieyes`; see [Static and on-request pages](/docs/getting-started/which-api#static-and-on-request-pages).

</Framework>

<Framework when="sveltekit">

On a page the server renders per request, the handle reads the region from the Vercel (`x-vercel-ip-country`, `x-vercel-ip-country-region`) or Cloudflare (`cf-ipcountry`) geo headers, and those headers are the only region source, for the banner and for the browser alike. A `region.detect` of yours is used only where the server reads nothing (a prerendered page, or `<CookieYesRoot>` rendered without `state`), once the page has loaded. Until then such a page shows the banner of the strictest regulation.

</Framework>

## Choosing a privacy law: the `regulation` option

| | `"GDPR"` | `"CCPA"` |
| --- | --- | --- |
| Optional categories before the visitor chooses | Off, the visitor opts in | On, the visitor opts out |
| Banner buttons | Accept All, Reject All, Customise | Do Not Sell |
| Global Privacy Control | Not used | Honoured |

Set the strictest law your visitors fall under, `"GDPR"` for most sites, and ship it for everyone. If you set nothing, the banner behaves as under `"GDPR"`. To choose per visitor, set `region` instead: it maps the visitor's country to a regulation. A manual `regulation` always wins over `region`, so set one or the other.

Under `"CCPA"`, a browser that sends Global Privacy Control starts the visitor opted out until they choose; `region.honorGpc: false` turns this off. The signal never changes which banner shows. To read it yourself, `readGpc()` returns `true` while the browser is sending it, and every [consent record](/docs/getting-started/self-hosted) carries it as `gpc`.

<Framework when="nextjs react vue svelte">

Under `"CCPA"`, render `<CookieOptOut />` next to the banner: Do Not Sell opens it.

</Framework>

<Framework when="nuxt sveltekit astro">

Under `"CCPA"`, `<CookieYesRoot />` renders `<CookieOptOut />` for you, and so it does when `region` can resolve to `"CCPA"`: Do Not Sell opens it.

</Framework>

## Consent categories

Leave `categories` out and you get the built-in five: `necessary` (required), `functional`, `analytics`, `performance` and `advertisement`. To use your own list:

<Framework when="nextjs react core">

```ts title="src/consent.ts"
import { initCookieYes } from "@cookieyes/core";

initCookieYes({
  mode: "cookie-only",
  categories: [
    { id: "necessary", required: true, label: "Essential" },
    { id: "analytics", label: "Analytics", gcm: ["analytics_storage"] },
    { id: "marketing", label: "Marketing", gcm: ["ad_storage", "ad_user_data"] },
  ],
});
```

</Framework>

Ids must be unique and contain no `,` or `:`, and one category must be `required: true`; otherwise the list is rejected with a console warning and the built-in five are used. Decide your ids early: adding, removing or renaming an id later makes every returning visitor choose again. Labels and descriptions can change freely.

## Where the choice is stored

`cookie-only` keeps the visitor's choice in a browser cookie and makes no network requests. Start here.

`self-hosted` also sends each choice to your server as a consent record, so you can keep proof of it. See [Self-hosted mode](/docs/getting-started/self-hosted) for what your server receives and how to store it.

## Common mistakes

**`'apiUrl' does not exist in type 'CookieYesOfflineConfig'`.**
You set `apiUrl` or `backend` under `mode: "cookie-only"`. Switch to `"self-hosted"` or remove them.

**`regulation is set manually, so region detection is ignored`.**
You set both `regulation` and `region`. Keep one.

**A custom category does not appear.**
Your `categories` list broke one of the rules above; the console warning says which. The built-in five are shown instead.
