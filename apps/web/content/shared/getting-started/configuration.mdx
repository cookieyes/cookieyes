<Framework when="nextjs react core">

`initCookieYes(config)` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default.

```ts check="false"
initCookieYes({
  mode: "cookie-only",
  regulation: "GDPR",
  theme: { primaryColor: "#1863dc" },
});
```

</Framework>

<Framework when="vue">

`app.use(CookieYes, config)` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default. The config is the same `CookieYesConfig` that `initCookieYes()` takes in the other packages.

```ts title="src/consent-manager.ts"
import type { App } from "vue";
import { CookieYes } from "@cookieyes/vue";

export function setupConsent(app: App): void {
  app.use(CookieYes, {
    mode: "cookie-only",
    regulation: "GDPR",
    theme: { primaryColor: "#1863dc" },
  });
}
```

</Framework>

<Framework when="nuxt">

The `cookieyes` key in `nuxt.config.ts` is where you configure CookieYes. It takes the same `CookieYesConfig` that `initCookieYes()` takes in the other packages. `mode` defaults to `"cookie-only"` here, so no option is required.

```ts title="nuxt.config.ts" group="config"
export default defineNuxtConfig({
  modules: ["@cookieyes/nuxt"],
  cookieyes: {
    regulation: "GDPR",
    theme: { primaryColor: "#1863dc" },
  },
});
```

Options that hold functions, such as `integrations`, `onConsentReady` and `onConsentUpdate`, go under the same key in `app/app.config.ts`. `nuxt.config.ts` becomes runtime config, which is JSON and drops functions; in development the module warns when it finds one there.

```ts title="app/app.config.ts" group="config"
export default defineAppConfig({
  cookieyes: {
    onConsentUpdate: (state) => {
      console.log("Consent saved", state.categories);
    },
  },
});
```

The module merges the two files. `app.config.ts` wins for a key set in both, and one level of nesting is merged, so `i18n.messages` in one file and `i18n.loadLanguage` in the other both apply. Arrays are replaced, not combined.

</Framework>

### `region`

<ConfigNestedTable path="region" />

<Framework when="nuxt">

Put `region.map` in `nuxt.config.ts`. On a page the server renders per request, the module reads the region from the Vercel or Cloudflare geo headers, and those headers are the only region source, for the banner and for the browser alike. A `region.detect` in `app/app.config.ts` is used only where the server reads nothing (`ssr: false`, `nuxt generate`, and routes with `swr`, `isr`, `cache` or `prerender` route rules), once the page has loaded.

</Framework>

### `i18n`

<Framework when="nextjs react vue nuxt">

`messages` per language, `locale`, `detectBrowserLanguage` and `loadLanguage`. See [Translations](/docs/translations).

<Framework when="core">

`messages` per language, each one partial with English filling the gaps; `locale` to pin the language; `detectBrowserLanguage` (default on); `loadLanguage(tag)` to fetch a language on demand.

### `networkBlocker`

<Framework when="nextjs react core">

`rules` for requests to block until a category is granted, plus `onRequestBlocked` and `logBlockedRequests`. Needs `registerNetworkBlocker()` called once before `initCookieYes()`. See [Network blocking](/docs/network-blocking).

</Framework>

<Framework when="nuxt">

## Choosing a privacy law: the `regulation` option

| | `"GDPR"` | `"CCPA"` |
| --- | --- | --- |
| Optional categories before the visitor chooses | Off, the visitor opts in | On, the visitor opts out |
| Banner buttons | Accept All, Reject All, Customise | Do Not Sell |
| Global Privacy Control | Not used | Honoured |

Set the strictest law your visitors fall under, `"GDPR"` for most sites, and ship it for everyone. If you set nothing, the banner behaves as under `"GDPR"`. To choose per visitor, set `region` instead: it maps the visitor's country to a regulation. A manual `regulation` always wins over `region`, so set one or the other.

Under `"CCPA"`, a browser that sends Global Privacy Control starts the visitor opted out until they choose; `region.honorGpc: false` turns this off. The signal never changes which banner shows. To read it yourself, `readGpc()` returns `true` while the browser is sending it, and every [consent record](/docs/getting-started/self-hosted) carries it as `gpc`.

<Framework when="nextjs react vue">

Under `"CCPA"`, render `<CookieOptOut />` next to the banner: Do Not Sell opens it.

</Framework>

<Framework when="nuxt">

Under `"CCPA"`, `<CookieYesRoot />` renders `<CookieOptOut />` for you, and so it does when `region` can resolve to `"CCPA"`: Do Not Sell opens it.

</Framework>

## Consent categories

Leave `categories` out and you get the built-in five: `necessary` (required), `functional`, `analytics`, `performance` and `advertisement`. To use your own list:

<Framework when="nextjs react core">

```ts title="src/consent.ts"
import { initCookieYes } from "@cookieyes/core";

initCookieYes({
  mode: "cookie-only",
  categories: [
    { id: "necessary", required: true, label: "Essential" },
    { id: "analytics", label: "Analytics", gcm: ["analytics_storage"] },
    { id: "marketing", label: "Marketing", gcm: ["ad_storage", "ad_user_data"] },
  ],
});
```

</Framework>

<Framework when="vue">

```ts title="src/consent-manager.ts"
import type { App } from "vue";
import { CookieYes } from "@cookieyes/vue";

export function setupConsent(app: App): void {
  app.use(CookieYes, {
    mode: "cookie-only",
    categories: [
      { id: "necessary", required: true, label: "Essential" },
      { id: "analytics", label: "Analytics", gcm: ["analytics_storage"] },
      { id: "marketing", label: "Marketing", gcm: ["ad_storage", "ad_user_data"] },
    ],
  });
}
```

</Framework>

<Framework when="nuxt">

```ts title="nuxt.config.ts"
export default defineNuxtConfig({
  modules: ["@cookieyes/nuxt"],
  cookieyes: {
    categories: [
      { id: "necessary", required: true, label: "Essential" },
      { id: "analytics", label: "Analytics", gcm: ["analytics_storage"] },
      { id: "marketing", label: "Marketing", gcm: ["ad_storage", "ad_user_data"] },
    ],
  },
});
```

</Framework>

Ids must be unique and contain no `,` or `:`, and one category must be `required: true`; otherwise the list is rejected with a console warning and the built-in five are used. Decide your ids early: adding, removing or renaming an id later makes every returning visitor choose again. Labels and descriptions can change freely.

## Where the choice is stored

`cookie-only` keeps the visitor's choice in a browser cookie and makes no network requests. Start here.

`self-hosted` also sends each choice to your server as a consent record, so you can keep proof of it. See [Self-hosted mode](/docs/getting-started/self-hosted) for what your server receives and how to store it.

## Common mistakes

**`'apiUrl' does not exist in type 'CookieYesOfflineConfig'`.**
You set `apiUrl` or `backend` under `mode: "cookie-only"`. Switch to `"self-hosted"` or remove them.

**`regulation is set manually, so region detection is ignored`.**
You set both `regulation` and `region`. Keep one.

**A custom category does not appear.**
Your `categories` list broke one of the rules above; the console warning says which. The built-in five are shown instead.
