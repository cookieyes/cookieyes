`initCookieYes(config)` is the one place you configure CookieYes. `mode` is the only required option; everything else has a sensible default.

```ts check="false"
initCookieYes({
  mode: "cookie-only",
  regulation: "GDPR",
  theme: { primaryColor: "#1863dc" },
});
```

## Choosing a privacy law: the `regulation` option

| | `"GDPR"` | `"CCPA"` |
| --- | --- | --- |
| Optional categories before the visitor chooses | Off, the visitor opts in | On, the visitor opts out |
| Banner buttons | Accept All, Reject All, Customise | Do Not Sell |
| Global Privacy Control | Not used | Honoured |

Set the strictest law your visitors fall under, `"GDPR"` for most sites, and ship it for everyone. If you set nothing, the banner behaves as under `"GDPR"`. To choose per visitor, set `region` instead: it maps the visitor's country to a regulation. A manual `regulation` always wins over `region`, so set one or the other.

<Framework when="nextjs react">

Under `"CCPA"`, render `<CookieOptOut />` next to the banner: Do Not Sell opens it.

</Framework>

## Consent categories

Leave `categories` out and you get the built-in five: `necessary` (required), `functional`, `analytics`, `performance` and `advertisement`. To use your own list:

```ts title="src/consent.ts"
import { initCookieYes } from "@cookieyes/core";

initCookieYes({
  mode: "cookie-only",
  categories: [
    { id: "necessary", required: true, label: "Essential" },
    { id: "analytics", label: "Analytics", gcm: ["analytics_storage"] },
    { id: "marketing", label: "Marketing", gcm: ["ad_storage", "ad_user_data"] },
  ],
});
```

Ids must be unique and contain no `,` or `:`, and one category must be `required: true`; otherwise the list is rejected with a console warning and the built-in five are used. Decide your ids early: adding, removing or renaming an id later makes every returning visitor choose again. Labels and descriptions can change freely.

## Where the choice is stored

`cookie-only` keeps the visitor's choice in a browser cookie and makes no network requests. Start here.

`self-hosted` also sends each choice to your server as a consent record, with a `POST` to `apiUrl`, so you can keep proof of it. `apiKey` goes in a `Bearer` header but is visible to anyone in the browser, so never treat it as a secret. For your own transport, pass a `backend` with a `persist(payload)` function instead of `apiUrl`, and throw from it when your server did not store the record.

Each record says who decided, what they chose, when, how and where:

```json
{
  "recordId": "9lBcA17N3AVZ.mul2v4rq.9wicmt",
  "consentId": "9lBcA17N3AVZ",
  "categories": {
    "necessary": true,
    "functional": false,
    "analytics": false,
    "performance": false,
    "advertisement": false
  },
  "regulation": "GDPR",
  "domain": "example.com",
  "decidedAt": "2026-09-28T10:01:21.638Z",
  "taxonomyHash": "2fbx48",
  "action": "reject_all",
  "source": "banner"
}
```

`decidedAt` is when the visitor decided, not when the record was sent. `action` is `accept_all`, `reject_all`, `accept_selected` or `save`, and `source` is `banner`, `preferences`, `optout`, or `api` for a call from your own code.

A record your server has not confirmed, with a `2xx` response or a `persist` that resolves, is kept in the visitor's browser and sent again: on the next page load, when the browser is back online, and on a timer while the page stays open. Up to 50 records are kept, for at most 7 days. A record can therefore reach your server more than once, so store each one by its `recordId` and ignore one you already have. Your server is where the proof lives; how long to keep it is for you and your legal team to decide.

## Common mistakes

**`'apiUrl' does not exist in type 'CookieYesOfflineConfig'`.**
You set `apiUrl` or `backend` under `mode: "cookie-only"`. Switch to `"self-hosted"` or remove them.

**Your server has the same decision twice.**
The record was sent again after your server stored it but its reply never reached the browser. Store records by `recordId`.

**A record that failed in your `backend` is never sent again.**
Your `persist` function resolved although the record was not stored. Throw when your server fails, for example `if (!res.ok) throw new Error(...)`.

**`regulation is set manually, so region detection is ignored`.**
You set both `regulation` and `region`. Keep one.

**A custom category does not appear.**
Your `categories` list broke one of the rules above; the console warning says which. The built-in five are shown instead.
