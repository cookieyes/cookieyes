<Framework when="core">

With no framework, there are two packages, and a third path if you are writing a framework adapter:

| You want | Use |
| --- | --- |
| The ready-made banner, dialogs and recall button on any page | [`@cookieyes/vanilla`](/docs/getting-started/vanilla) |
| A banner of your own, drawn from the consent state | [`@cookieyes/core`](/docs/store/build-your-own-ui) |
| A native banner for a framework that has no CookieYes adapter yet | [`@cookieyes/ui`](/docs/store/build-an-adapter), checked by the shared conformance suite |

Start with `@cookieyes/vanilla`: it is the same banner as the React one, with the same styling and translations. For Vue 3, use `@cookieyes/vue` instead: it has its own plugin, components and composables.

</Framework>

<Framework when="nextjs react">

Most apps need only `CookieBanner` and `CookiePreferences`, styled with a `theme`. Read on if the defaults do not fit your design, or you need consent somewhere other than the banner.

## Pick a layer

| Layer | You write | Choose when |
| --- | --- | --- |
| **Presets**: `CookieBanner`, `CookiePreferences`, `RecallButton` | Nothing. Theme with `theme` config or [CSS](/docs/styling/custom-css) | The default. Start here |
| **Primitives**: `Banner.*`, `Preferences.*`, `OptOut.*` | Your markup and classes; behaviour and accessibility come built in | Your design system needs its own markup |
| **Hooks**: `useConsent()`, `useConsentActions()` | Everything | You are building something that is not a banner |

The layers mix freely. A common setup is the preset banner, a preferences dialog built from primitives to match a design system, and one hook to load analytics.

## Read and change consent

Two hooks cover almost every custom need. `useConsent()` reads the state and re-renders when it changes; `useConsentActions()` changes it and never re-renders.

```tsx title="app/consent-status.tsx"
"use client";

import { useConsent, useConsentActions } from "@cookieyes/react";

export function ConsentStatus() {
  const { hasActed, committedCategories } = useConsent();
  const { showPreferences } = useConsentActions();

  if (!hasActed) return null;
  return (
    <p>
      Analytics: {committedCategories.analytics ? "on" : "off"}{" "}
      <button type="button" onClick={showPreferences}>Change</button>
    </p>
  );
}
```

## Gate on committed values

`useConsent()` exposes two views of the categories. `categories` is the live copy and changes on every toggle in the dialog, even before Save. `committedCategories` changes only on a real decision: accept, reject, save or reset.

Load scripts, embeds and trackers from `committedCategories`, or from `useConsentCategory()`, which reads the committed value for one category. Use `categories` only to drive your own dialog's checkboxes.

## Common mistakes

**A script loads as soon as someone flips a toggle, before Save.**
It reads `categories` (live) instead of `committedCategories` or `useConsentCategory()` (committed).

**A primitive renders but does nothing.**
It sits outside its root. Every `Preferences.*` must be inside `Preferences.Root`, every `Banner.*` inside `Banner.Root`, every `OptOut.*` inside `OptOut.Root`.

**You rebuilt the banner with hooks to change one button.**
You wanted [Custom CSS](/docs/styling/custom-css) or the primitives. The presets can be restyled part by part without replacing them.

## Read and change consent

Import the functions in a `<script>` of a component, or in an island. They wait for the SDK to start, so they work even when they run first. `getConsent()` is a snapshot, not a live value: to react to a change, use `onConsentChange()`.

```astro title="src/components/ConsentStatus.astro"
<p id="consent-status" hidden>
  Analytics: <span id="consent-analytics"></span>
  <button type="button" id="consent-change">Change</button>
</p>

<script>
  import { getConsent, onConsentChange, openPreferences } from "@cookieyes/astro/client";

  const status = document.getElementById("consent-status");
  const analytics = document.getElementById("consent-analytics");

  const consent = await getConsent();
  if (status && consent.hasActed) status.hidden = false;

  onConsentChange("change", ({ categories }) => {
    if (analytics) analytics.textContent = categories.analytics ? "on" : "off";
  });
  document.getElementById("consent-change")?.addEventListener("click", openPreferences);
</script>
```

## Static and on-request pages

On a prerendered page the HTML is the same for every visitor, so nothing about one visitor is in it. The banner is in the HTML, hidden, and a small inline script in `<head>` reads the consent cookie before first paint: a first-time visitor sees the banner at once, a returning visitor never sees it, and no request is made. `Astro.locals.cookieyes` on such a page holds safe defaults: `read` is `false`, `initialConsent` is `null`, and only the required categories are `true`. `getServerConsent(Astro)` returns `null` and `getServerRegion(Astro)` returns an empty region.

On a page rendered on request (`export const prerender = false`, or a server `output`), the integration reads the request: the consent cookie, the Vercel and Cloudflare geo headers, `Sec-GPC`, and in development the DevTools region override. A visitor who already chose gets no banner markup, and with a `region` map a visitor the headers place in California gets the CCPA banner from the first byte.

```astro title="src/pages/account.astro"
---
import { getServerConsent, getServerRegion } from "@cookieyes/astro/server";
import Layout from "../layouts/Layout.astro";

export const prerender = false;

const consent = getServerConsent(Astro);
const { region } = getServerRegion(Astro);
---
<Layout>
  <p>Decided: {consent ? "yes" : "no"}. Region: {region ?? "unknown"}.</p>
</Layout>
```

A page that reads the request is different for each visitor, so it is sent with `Cache-Control: private` and `Vary: Cookie`, unless your page already sets its own `Cache-Control`. Never put such a page in a shared cache: a CDN that cached the HTML rendered for a California visitor would serve the CCPA banner to visitors elsewhere. If the page does not need the visitor, prerender it instead, which makes one HTML for everyone.

## Common mistakes

**A script loads as soon as someone flips a toggle, before Save.**
It reads `consents` (live) instead of `committedConsents` or `getConsentCategory()` (committed).

**`getConsent()` shows an old value.**
It is a snapshot taken when it resolved. Subscribe with `onConsentChange()` to follow later decisions.

**An on-request page is served from a CDN cache.**
The page sets its own shared `Cache-Control`. The integration keeps it and, in development, warns. Prerender the page or drop the directive.
