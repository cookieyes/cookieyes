One command in your existing project. The CLI detects your framework, asks a few questions and writes the setup for you, including the stylesheet import that is easy to forget. It runs locally and collects no data.

Prefer to write the files yourself? [Installation](/docs/getting-started/installation) is the same result in three steps.

## 1. Run the CLI

```npm
npx @cookieyes/cli init
```

## 2. Answer the questions

1. **Framework**: detected for you, just confirm.
2. **Backend mode**: choose **Cookie-only**. The choice is stored in the visitor's browser and no server is needed. Pick Self-hosted only if you must keep a record on your own server; it then asks for the URL.
3. **Privacy regulation**: `GDPR` for most sites, `CCPA` for California-style opt-out.
4. **Colour scheme**: light, dark, or follow the system.
5. **Extra languages**: English is always included.
6. Confirm, and it installs the package.

To skip the questions, in a script, in CI or from an AI coding tool, pass the answers as flags. `--yes` takes the default for any question left:

```npm
npx @cookieyes/cli init --yes --regulation GDPR --no-install
```

`npx @cookieyes/cli --help` lists every flag.

## 3. Start your app

The banner appears at the bottom of the page. Click **Accept All** and reload: it stays away, and a small round button in the corner reopens the preferences dialog.

## What it wrote

<Framework when="nextjs">

- `components/consent-manager/provider.tsx`: the configuration, the stylesheet import and the components, in one client file.
- `components/consent-manager/index.tsx`: lets you import `CookieYesRoot` from the folder.
- `app/layout.tsx` (or `pages/_app.tsx`): `<CookieYesRoot />` added to your existing layout.

</Framework>

<Framework when="react">

- `components/consent-manager/provider.tsx`: the configuration, the stylesheet import and the components, in one file.
- `components/consent-manager/index.tsx`: lets you import `CookieYesRoot` from the folder.
- Your entry file: `<CookieYesRoot />` added next to `<App />`.

</Framework>

<Framework when="vue">

- `src/consent-manager.ts` (`.js` in a JavaScript project): the configuration, the stylesheet import and `setupConsent(app)`, which installs the plugin.
- `src/components/CookieYesRoot.vue`: the banner, the preferences dialog and the recall button.
- `src/main.ts`: `setupConsent(app)` called after `createApp` and before `mount`.
- `src/App.vue`: `<CookieYesRoot />` added before your page content.

</Framework>

<Framework when="svelte">

- `src/lib/cookieyes.ts` (`.js` in a JavaScript project): the configuration.
- `src/lib/CookieYesRoot.svelte`: the provider with the banner, the preferences dialog and the recall button.
- `src/main.ts`: the stylesheet import.
- `src/App.svelte`: `<CookieYesRoot />` added at the end of your markup.

</Framework>

<Framework when="sveltekit">

- `src/lib/cookieyes.ts` (`.js` in a JavaScript project): the configuration.
- `src/hooks.server.ts`: `export const handle = cookieyesHandle(config)`, or `cookieyesHandle(config)` added to the `sequence()` of a handle you already have.
- `src/routes/+layout.server.ts`: `export const load = loadConsent`.
- `src/routes/cookieyes/styles.css/+server.ts`: the stylesheet route.
- `src/routes/+layout.svelte`: your page wrapped in `<CookieYesRoot {config} state={data.consent}>`.
- `src/app.d.ts`: the `/// <reference types="@cookieyes/sveltekit" />` line.

With `adapter-static` there is no server to read requests: the CLI then writes no `+layout.server.ts`, renders `<CookieYesRoot {config}>` without `state`, and adds `export const prerender = true;` to the stylesheet route.

</Framework>

<Framework when="nuxt">

- `nuxt.config.ts`: `@cookieyes/nuxt` added to `modules`.
- `app/app.config.ts` (`.js` in a JavaScript project): the configuration, under the `cookieyes` key.
- `app/app.vue`: `<CookieYesRoot />` added before your page content.

</Framework>

<Framework when="nextjs react">

Files that already exist are left alone. If the CLI cannot find where to add `<CookieYesRoot />`, it prints the lines to paste under "Manual step needed".

To change anything later, edit `provider.tsx`: every option is on [Configuration](/docs/getting-started/configuration).

</Framework>

<Framework when="vue">

Files that already exist are left alone. If the CLI cannot find where to add `setupConsent(app)` or `<CookieYesRoot />`, it prints the lines to paste under "Manual step needed".

To change anything later, edit `src/consent-manager.ts`: every option is on [Configuration](/docs/getting-started/configuration).

In a Nuxt project, choose Nuxt instead: the CLI then sets up `@cookieyes/nuxt`. See the [Nuxt quick start](/docs/nuxt/getting-started/quick-start).

</Framework>

<Framework when="svelte">

Files that already exist are left alone. If the CLI cannot find where to add the stylesheet import or `<CookieYesRoot />`, it prints the lines to paste under "Manual step needed".

The hooks work only inside `<CookieYesRoot>`. To use them in your own components, move your page content inside it: `<CookieYesRoot>...</CookieYesRoot>`.

To change anything later, edit `src/lib/cookieyes.ts`: every option is on [Configuration](/docs/getting-started/configuration).

In a SvelteKit project, choose SvelteKit instead: the CLI then sets up `@cookieyes/sveltekit`. See the [SvelteKit quick start](/docs/sveltekit/getting-started/quick-start).

</Framework>

<Framework when="nuxt">

Files that already exist are left alone. An `app.config.ts` you already have is not changed: the CLI prints the `cookieyes` key to add under "Manual step needed", and does the same when it cannot add the module or `<CookieYesRoot />`.

To change anything later, edit `app/app.config.ts`: every option is on [Configuration](/docs/getting-started/configuration). Options there are merged with any `cookieyes` key in `nuxt.config.ts`, and `app.config.ts` wins.

</Framework>

<Framework when="sveltekit">

Files that already exist are left alone. If the CLI cannot add the handle, the `load` or `<CookieYesRoot>` to a file you already have, it prints the lines to paste under "Manual step needed". An existing `+layout.server.ts` is never changed: return `...loadConsent(event)` from its `load`.

To change anything later, edit `src/lib/cookieyes.ts`: every option is on [Configuration](/docs/getting-started/configuration).

</Framework>

## Common mistakes

**The banner does not appear.**
You already chose in this browser. Delete the `cookieyes-consent` cookie and reload.

<Framework when="nextjs react">

**The banner is unstyled text.**
The stylesheet import was removed from `provider.tsx`. Put it back.

</Framework>

<Framework when="vue">

**The banner is unstyled text.**
The stylesheet import was removed from `src/consent-manager.ts`. Put it back.

</Framework>

<Framework when="svelte">

**The banner is unstyled text.**
The stylesheet import was removed from `src/main.ts`. Put it back.

**`could not find CookieYes` in the console.**
A component outside `<CookieYesRoot>` uses a hook. Move it inside.

</Framework>

<Framework when="nuxt">

**`Failed to resolve component: CookieYesRoot` in the console.**
`@cookieyes/nuxt` is missing from `modules` in `nuxt.config.ts`. Add it back.

</Framework>

<Framework when="sveltekit">

**The banner is unstyled text.**
The stylesheet route `src/routes/cookieyes/styles.css/+server.ts` was removed or moved. Put it back, or set `stylesHref` on the handle to where it lives now.

**`loadConsent() found no event.locals.cookieyes` in the server log.**
`cookieyesHandle(config)` is no longer in `src/hooks.server.ts`. Add it back.

</Framework>

**"Manual step needed" was printed.**
Paste the printed lines into your layout or entry file. Nothing else is missing.
