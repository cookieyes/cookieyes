## Set it up

Import the SDK's stylesheet **after** Tailwind. Tailwind's preflight resets buttons and headings; loaded after the SDK, it would strip the banner's own button styles.

<Framework when="nextjs react">

```css title="app/globals.css"
@import "tailwindcss";
@import "@cookieyes/react/styles.css";
```

</Framework>

<Framework when="vue">

```css title="src/styles.css"
@import "tailwindcss";
@import "@cookieyes/vue/styles.css";
```

</Framework>

<Framework when="svelte">

```css title="src/styles.css"
@import "tailwindcss";
@import "@cookieyes/svelte/styles.css";
```

</Framework>

<Framework when="sveltekit">

```css title="src/app.css"
@import "tailwindcss";
@import "@cookieyes/sveltekit/styles.css";
```

Import the file in `src/routes/+layout.svelte`. The handle still writes the SDK's critical CSS and stylesheet link right after `<meta charset>`, before Tailwind. The copy imported here comes after Tailwind, which is the order that counts; both copies hold the same rules.

</Framework>

<Framework when="astro">

```css title="src/styles/global.css"
@import "tailwindcss";
@import "@cookieyes/astro/styles.css";
```

Import the file in your layout. The integration still writes the SDK's critical CSS and stylesheet link right after `<meta charset>`, before Tailwind. The copy imported here comes after Tailwind, which is the order that counts; both copies hold the same rules.

</Framework>

Load the file with `css: ["~/assets/css/main.css"]` in `nuxt.config.ts`. The module still writes the SDK's stylesheet right after `<meta charset>`, before Tailwind. The copy imported here comes after Tailwind, which is the order that counts; both copies hold the same rules.

</Framework>

## Three ways to use utilities

**On a component.** `className` is added to the component's own classes:

```tsx check="false"
<CookieBanner className="shadow-2xl ring-1 ring-black/5" />
```

`RecallButton` is the exception: its `className` replaces the default class. Keep `cy-widget` if you want the default look: `<RecallButton className="cy-widget ring-2" />`.

</Framework>

## Three ways to use utilities

**On a component.** `class` is added to the component's own classes:

```svelte title="src/lib/CookieYesRoot.svelte"
<script lang="ts">
  import type { Snippet } from "svelte";
  import {
    CookieBanner,
    CookiePreferences,
    CookieYesProvider,
    RecallButton,
  } from "@cookieyes/svelte";
  import { config } from "./cookieyes";

  let { children }: { children?: Snippet } = $props();
</script>

<CookieYesProvider {config}>
  <CookieBanner class="shadow-2xl ring-1 ring-black/5" />
  <CookiePreferences />
  <RecallButton />
  {@render children?.()}
</CookieYesProvider>
```

```ts title="src/lib/cookieyes.ts"
import type { CookieYesConfig } from "@cookieyes/svelte";

export const config: CookieYesConfig = { mode: "cookie-only", regulation: "GDPR" };
```

`RecallButton` is the exception: its `class` replaces the default class. Keep `cy-widget` if you want the default look: `<RecallButton class="cy-widget ring-2" />`.

</Framework>

## Three ways to use utilities

**On a component.** `class` is added to the component's own classes. Pass the components to `<CookieYesRoot>` in a `ui` snippet, which replaces the ones it renders by default, so list each one you want, and `<CookieOptOut />` too if a CCPA regulation can apply:

```svelte title="src/routes/+layout.svelte"
<script lang="ts">
  import {
    CookieBanner,
    CookiePreferences,
    CookieYesRoot,
    RecallButton,
  } from "@cookieyes/sveltekit";
  import { config } from "../lib/cookieyes";

  let { data, children } = $props();
</script>

<CookieYesRoot {config} state={data.consent}>
  {#snippet ui()}
    <CookieBanner class="shadow-2xl ring-1 ring-black/5" />
    <CookiePreferences />
    <RecallButton />
  {/snippet}
  {@render children()}
</CookieYesRoot>
```

`RecallButton` is the exception: its `class` replaces the default class. Keep `cy-widget` if you want the default look: `<RecallButton class="cy-widget ring-2" />`.

</Framework>

<Framework when="astro">

## Three ways to use utilities

**On a component.** `class` is added to the component's own classes. Pass the components to `<CookieYesRoot>`'s default slot, which replaces the ones it renders by default, so list each one you want, and `<CookieOptOut />` too if a CCPA regulation can apply:

```astro title="src/layouts/Layout.astro"
---
import {
  CookieBanner,
  CookiePreferences,
  CookieYesRoot,
  RecallButton,
} from "@cookieyes/astro/components";
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
  </head>
  <body>
    <CookieYesRoot>
      <CookieBanner class="shadow-2xl ring-1 ring-black/5" />
      <CookiePreferences />
      <RecallButton />
    </CookieYesRoot>
    <slot />
  </body>
</html>
```

`RecallButton` takes `class` too, and it merges with the default `cy-widget` class instead of replacing it, so `<RecallButton class="ring-2" />` keeps the default look.

</Framework>

## Good to know

- A utility has the same strength as the SDK's own rule, so it wins only if your CSS comes after `styles.css`. Do not use the `!` modifier or `@layer components` for these rules; both hide the ordering problem instead of fixing it.
<Framework when="nextjs react vue nuxt svelte sveltekit core">

- The components render into `<body>`, so `group-` and `peer-` variants from your tree do not reach them.

</Framework>

<Framework when="astro">

- The banner renders where `<CookieYesRoot />` is and the dialogs into `<body>`, so `group-` and `peer-` variants from your tree do not reach them.

</Framework>


- The SDK does not read Tailwind's `dark` class. Set `colorScheme` to match your default scheme and switch the variables from `html.dark`: see [Colour scheme](/docs/styling/color-scheme).
<Framework when="nextjs react">

- Arbitrary values set the SDK's variables: `<CookieBanner className="[--cy-primary:#7c3aed]" />`. This works only while `primaryColor` is not set in `theme`.

</Framework>

<Framework when="vue nuxt svelte sveltekit astro">

</Framework>


## Common mistakes

**The banner's buttons look like plain text.**
Tailwind loaded after the SDK's stylesheet. Put the `@cookieyes` stylesheet import last.

<Framework when="nextjs react">

**A utility on `<CookieBanner>` does nothing.**
Your CSS comes before `styles.css`, or the value is set in `theme`.

**`<RecallButton className="...">` lost its style.**
`className` replaces the default class there. Include `cy-widget`.

</Framework>
