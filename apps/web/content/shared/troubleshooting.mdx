Most problems here are a setup detail, and several show no error at all. Find what you see in the table; each row is one line to check.

## Find your symptom

<Framework when="nextjs react">

| What you see | Cause | Fix |
| --- | --- | --- |

| Customise or your own "Cookie settings" link does nothing | `<CookiePreferences />` is not rendered | Render it next to the banner |
| A tracker loads when a switch is flipped, before Save | You read the live values | Use `useConsentCategory()` or `committedCategories`, see [useConsent](/docs/hooks/use-consent#saved-values-vs-live-values) |

| The banner flashes and vanishes for returning visitors | The server did not know their choice | Pass `initialConsent`, see [Runtime and server helpers](/docs/hooks/low-level-hooks#read-a-returning-visitors-consent-on-the-server) |
| Your CSS rule does nothing | Your stylesheet loads before the SDK's, or a `theme` value sets the same property inline | Import yours after `styles.css`; see [Custom CSS](/docs/styling/custom-css) |
| Scoped CSS or CSS Modules never reach the banner | The components render into `<body>` | Use global CSS with `data-cy-part` selectors |
| Tracking continues after the visitor withdraws consent | A script that already ran cannot be unloaded | Render [`ReloadNotice`](/docs/components/reload-notice) |

| A checkbox in your own dialog turns on but never off | `onChange={toggle}` passes the event | Use `onChange={(e) => toggle(e.target.checked)}` |
| Focus jumps to the top of the page when a dialog closes | The dialog was opened through the runtime directly | Open it with `useConsentActions().showPreferences()` |
| The banner is not where you put it in your code | It moves to the top of `<body>` so keyboard users reach it first | Expected. See [Accessibility](/docs/accessibility) |

## Console messages

<Framework when="nextjs react">

**`[cookieyes] No runtime is registered. Call initCookieYes(...) in a 'use client' module before using hooks or components.`**
Thrown only by `useConsentRuntime()` and `getCookieYes()`, when they run before `initCookieYes()` or during server rendering. Every other hook returns a default instead. See [Runtime and server helpers](/docs/hooks/low-level-hooks).

**`[cookieyes] OptOut.* sub-components must be rendered inside <OptOut.Root>.`**
An `OptOut.*` piece sits outside `OptOut.Root`. Move it inside.

**`` [cookieyes] `asChild` expects exactly one React element child. ``**
You passed text, a fragment or two elements to a piece with `asChild`. Pass exactly one element.

</Framework>

<Framework when="vue">

**`[cookieyes] useConsent() could not find CookieYes. Add app.use(CookieYes, config) before mounting the app.`**
Thrown by every composable and component when the plugin is missing; the name at the start is the one that threw, such as `useConsent()` or `<CookieBanner>`. `app.use(CookieYes, config)` has not run on the app that renders it. When the message ends with `and call composables inside setup() or app.runWithContext()`, the composable also ran outside `setup()`: move the call into `setup()`.

**`[cookieyes] getCookieYes() found no runtime. Install the plugin first: app.use(CookieYes, config).`**
Thrown by `getCookieYes()` when it runs before the plugin. Every composable throws the message above instead. See [Runtime and server helpers](/docs/hooks/low-level-hooks).

**`[cookieyes] app.use(CookieYes) ran again with a different config. Replacing the previous runtime.`**
The plugin was installed a second time in the browser with another config object. Install it once, with one config.

**`[cookieyes] OptOut.* sub-components must be rendered inside <OptOut.Root>.`**
An `OptOut.*` piece sits outside `OptOut.Root`. Move it inside. `Preferences.*` pieces give the same message about `<Preferences.Root>`.

**`` [cookieyes] `asChild` expects exactly one element child. ``**
You passed text, a fragment or two elements to a piece with `asChild`. Pass exactly one element.

</Framework>

<Framework when="nuxt">

**`` ... in nuxt.config.ts holds a function, which runtime config drops because it is JSON. Move it under `cookieyes` in app.config.ts. ``**
A development warning from the module, naming the option, such as `cookieyes.onConsentUpdate`. Move that option to `app/app.config.ts`.

**`[cookieyes] useConsent() could not find CookieYes. Add app.use(CookieYes, config) before mounting the app, and call composables inside setup() or app.runWithContext().`**
The module installs the plugin for you, so in a Nuxt app this means the composable ran outside a component's `setup()`, for example inside an event handler. Call it at the top of `<script setup>` and use what it returns.

**`[cookieyes] <CookieYesRoot /> needs the @cookieyes/nuxt module in modules.`**
`<CookieYesRoot />` rendered without the module's plugin. Add `@cookieyes/nuxt` to `modules` in `nuxt.config.ts`.

**`[cookieyes] OptOut.* sub-components must be rendered inside <OptOut.Root>.`**
An `OptOut.*` piece sits outside `OptOut.Root`. Move it inside. `Preferences.*` pieces give the same message about `<Preferences.Root>`.

**`` [cookieyes] `asChild` expects exactly one element child. ``**
You passed text, a fragment or two elements to a piece with `asChild`. Pass exactly one element.

</Framework>

<Framework when="svelte">

**`[cookieyes] useConsent() could not find CookieYes. Wrap the app in <CookieYesProvider config={...}> and call hooks while a component initialises.`**
Thrown by every hook and component when no `<CookieYesProvider>` is above it; the name at the start is the one that threw, such as `useConsent()` or `<CookieBanner>`. It is also thrown when a hook runs after the component initialised, for example inside an event handler. Render the component inside the provider, and call hooks at the top of its `<script>`.

**`[cookieyes] getCookieYes() found no runtime. Mount <CookieYesProvider config={...}> first.`**
Thrown by `getCookieYes()` when it runs before the provider. Every hook throws the message above instead. See [Runtime and server helpers](/docs/hooks/low-level-hooks).

**`[cookieyes] <CookieYesProvider> ran again with a different config. Replacing the previous runtime.`**
The provider rendered a second time in the browser with another config object. Import one module-level `config`, as in `src/lib/cookieyes.ts`, instead of writing it inline.

**`[cookieyes] OptOut.* sub-components must be rendered inside <OptOut.Root>.`**
An `OptOut.*` piece sits outside `OptOut.Root`. Move it inside. `Preferences.*` pieces give the same message about `<Preferences.Root>`.

</Framework>

<Framework when="astro">

**`[cookieyes] Add cookieyes() to integrations in astro.config.mjs.`**
Logged once on the server when a component renders without the integration. Add `cookieyes()` to `integrations`.

**`[cookieyes] <CookieBanner /> needs <CookieYesRoot /> in your layout.`**
A development message in the browser, naming whichever component it found: the page has CookieYes components but no `<CookieYesRoot />`. The same message appears for a page reached through `<ClientRouter />` that lacks a root. Render the root once in the layout.

**`[cookieyes] Two <CookieYesRoot /> on this page; the first is used.`**
Logged on the server. Keep one root.

**`[cookieyes] The preferences dialog was opened, but <CookiePreferences /> is not in <CookieYesRoot /> on this page.`**
A development message in the browser. A default slot in `<CookieYesRoot>` left the dialog out; add `<CookiePreferences />` to the slot.

**`` [cookieyes] `categories` differ between astro.config.mjs and src/cookieyes.client.ts. Move them to astro.config.mjs, where the head script that decides first paint sees them. ``**
A development message in the browser. Keep `categories` in the Astro config.

**`` ... in astro.config.mjs holds a function, which is dropped because the config reaches the browser as JSON. Move it to src/cookieyes.client.ts. ``**
A development warning from the integration, naming the option, such as `cookieyes.onConsentUpdate`. Move that option to `src/cookieyes.client.ts`.

**`[cookieyes] /path reads the visitor's consent and region but is sent with "Cache-Control: ...", so a shared cache can serve one visitor's banner to another.`**
A development warning on a page rendered on request that sets its own shared `Cache-Control`. Prerender the page, or drop the shared directive.

</Framework>

<Framework when="sveltekit">

**`[cookieyes] loadConsent() found no event.locals.cookieyes. Add cookieyesHandle(config) to src/hooks.server.ts.`**
Thrown on the server by `loadConsent` when the handle did not run for the request. Export `handle = cookieyesHandle(config)` from `src/hooks.server.ts`; with a handle of your own, use `sequence(cookieyesHandle(config), yourHandle)`.

**`` [cookieyes] <CookieYesRoot> needs a `config` prop: the same object cookieyesHandle() takes, imported from one shared module. ``**
`<CookieYesRoot>` rendered without `config`. Import it from `src/lib/cookieyes.ts` and pass it: `<CookieYesRoot {config} state={data.consent}>`.

**`[cookieyes] useConsent() could not find CookieYes. Wrap the app in <CookieYesProvider config={...}> and call hooks while a component initialises.`**
Thrown by every hook and component when it is not rendered inside `<CookieYesRoot>`, which renders the provider the message names; the name at the start is the one that threw, such as `useConsent()` or `<CookieBanner>`. It is also thrown when a hook runs after the component initialised, for example inside an event handler. Render the page through `{@render children()}` inside `<CookieYesRoot>`, and call hooks at the top of a component's `<script>`.

**`[cookieyes] getCookieYes() found no runtime. Mount <CookieYesProvider config={...}> first.`**
Thrown by `getCookieYes()` when it runs on the server or before `<CookieYesRoot>` mounted. Call it from browser code. See [Runtime and server helpers](/docs/hooks/low-level-hooks).

**`[cookieyes] OptOut.* sub-components must be rendered inside <OptOut.Root>.`**
An `OptOut.*` piece sits outside `OptOut.Root`. Move it inside. `Preferences.*` pieces give the same message about `<Preferences.Root>`.

</Framework>

**`[cookieyes] Invalid categories config (...). Falling back to the default five`**
Your `categories` list broke a rule; the reason is in the brackets. The built-in five are shown until you fix it.

**`` [cookieyes] `regulation` is set manually, so region detection is ignored. ``**
You set both `regulation` and `region`. Keep one.

**`[cookieyes] no translations for language "..."; staying on "..."`**
You switched to a language that is not in `i18n.messages` and has no `loadLanguage`. Add the catalogue.

<Framework when="nextjs react vue svelte sveltekit astro">

**`[cookieyes] blocked POST https://... (rule "...", category: ...)`**
Not an error: network blocking stopped a request, as configured. Set `logBlockedRequests: false` to silence it.

</Framework>

## Reset and re-test

**Make the banner come back.** Delete the `cookieyes-consent` cookie in DevTools → Application → Cookies, or run this in the console and reload:

```js title="Console"
document.cookie = "cookieyes-consent=; max-age=0; path=/";
```

<Framework when="nextjs react vue nuxt svelte sveltekit">

Or call `useConsentActions().reset()` from a button you show only in development.

</Framework>

<Framework when="astro">

Or call `getConsentActions().reset()` from a button you show only in development.

</Framework>

**See the banner from any location.** Set `regulation: "GDPR"` while developing instead of relying on `region` detection.

<Framework when="astro">

**Devtools.** `@cookieyes/devtools`, the in-page debugging panel, is for React and Next.js only for now. It does not work with Astro.

</Framework>

**Check which version a page runs.** In the console:

```js title="Console"
window.CookieYesSDK; // { version: "x.y.z" }
```

The SDK sets this in the browser on every page where it starts, whether or not the banner shows, so public technology scanners can recognise the SDK. It holds the `@cookieyes/core` version and nothing else.

**Trigger the reload notice.** Accept the category, reload so the tool starts, then withdraw it. Rejecting on a first visit never shows it, because nothing was running.
