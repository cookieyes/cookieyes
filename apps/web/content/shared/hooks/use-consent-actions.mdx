## What it does

<Framework when="nextjs react">

Returns the functions that change consent or open a dialog. Use it to build your own controls: a "Cookie settings" link in the footer, an accept button in a custom banner, a reset button on a settings page. It only writes, so a component that calls it never re-renders when consent changes. To read consent, use [`useConsent()`](/docs/hooks/use-consent).

</Framework>

<Framework when="vue nuxt">

Returns the functions that change consent or open a dialog. Use it to build your own controls: a "Cookie settings" link in the footer, an accept button in a custom banner, a reset button on a settings page. It only writes, so it does not track consent changes. To read consent, use [`useConsent()`](/docs/hooks/use-consent).

</Framework>

You do not need it with `CookieBanner` or the [Banner primitives](/docs/headless/banner): their buttons already call these functions.

## Example

The most common use, a link that reopens the preferences dialog:

<Framework when="nextjs react">

```tsx title="app/cookie-settings-link.tsx"
"use client";

import { useConsentActions } from "@cookieyes/react";

export function CookieSettingsLink() {
  const { showPreferences } = useConsentActions();
  return (
    <button type="button" onClick={showPreferences}>
      Cookie settings
    </button>
  );
}
```

</Framework>

<Framework when="vue">

```vue title="src/components/CookieSettingsLink.vue"
<script setup lang="ts">
import { useConsentActions } from "@cookieyes/vue";

const { showPreferences } = useConsentActions();
</script>

<template>
  <button type="button" @click="showPreferences">Cookie settings</button>
</template>
```

</Framework>

<Framework when="nuxt">

```vue title="app/components/CookieSettingsLink.vue"
<script setup lang="ts">
const { showPreferences } = useConsentActions();
</script>

<template>
  <button type="button" @click="showPreferences">Cookie settings</button>
</template>
```

</Framework>

Use a real `<button>` or an `<a href>`, so keyboard and screen-reader users can reach it. The dialog moves focus into itself when it opens and back to your button when it closes.

## The actions

| Action | What it does | Saves? |
| --- | --- | --- |
| `acceptAll()` | Grants every category | Yes |
| `rejectAll()` | Rejects every optional category | Yes |
| `acceptSelected(ids)` | Grants exactly these categories and rejects the rest | Yes |
| `updateCategory(id, value)` | Changes one switch in the dialog, nothing more | No |
| `save()` | Saves the switches as they are | Yes |
| `reset()` | Forgets the decision; the banner shows again | Yes |
| `dismissBanner()` | Hides the banner for this page view; it returns on the next load | No |
| `showPreferences()`, `hidePreferences()` | Open and close the preferences dialog | |
| `showOptOut()`, `hideOptOut()` | Open and close the CCPA Do Not Sell dialog | |

## Good to know

**`updateCategory` does not save.** It changes the live value, like a switch in the dialog. Call `save()` when the visitor confirms. To grant something in one step, use `acceptSelected([...])` instead.

**`acceptSelected` replaces the whole list.** Categories you leave out are rejected. To add one category to the current choices, read `committedCategories` from `useConsent()`, add the id, and pass the full list.

<Framework when="nextjs react">

**Tell the consent record where your controls are.** In `mode: "self-hosted"` every decision is sent as a [consent record](/docs/getting-started/self-hosted) with a `source`. Pass it once, `useConsentActions("banner")` (or `"preferences"`, `"optout"`), and every action from that hook records it. Without it, decisions are recorded as `"api"`. The actions still take no arguments, so `onClick={acceptAll}` works as before.

</Framework>

<Framework when="vue nuxt">

**Tell the consent record where your controls are.** In `mode: "self-hosted"` every decision is sent as a [consent record](/docs/getting-started/self-hosted) with a `source`. Pass it once, `useConsentActions("banner")` (or `"preferences"`, `"optout"`), and every action from that hook records it. Without it, decisions are recorded as `"api"`. The actions still take no arguments, so `@click="acceptAll"` works as before.

</Framework>

<Framework when="nextjs react">

**Before the runtime is ready** (on the server, or if `initCookieYes()` has not run), every action is a silent no-op. Nothing throws.

</Framework>

<Framework when="vue">

**Without the plugin it throws.** If `app.use(CookieYes, config)` has not run, calling `useConsentActions()` throws "could not find CookieYes". Call it inside `setup()`.

</Framework>

<Framework when="nuxt">

**Call it inside `setup()` or `<script setup>`.** The module installs the plugin before any component renders, so there is nothing else to set up.

</Framework>

## Common mistakes

**Switches change but nothing is saved.**
You called `updateCategory()` without `save()`.

**Granting one category rejected the others.**
`acceptSelected()` replaces the whole list. Pass every category you want granted.

**`showPreferences()` does nothing.**
`CookiePreferences` (or your own `Preferences.Root`) is not rendered. The action only opens it.

<Framework when="nextjs react">

**Nothing happens and there is no error.**
`initCookieYes()` did not run. See [Installation → Common mistakes](/docs/getting-started/installation#common-mistakes).

</Framework>

<Framework when="vue">

**It throws "could not find CookieYes".**
`app.use(CookieYes, config)` did not run before the app mounted. See [Installation → Common mistakes](/docs/getting-started/installation#common-mistakes).

</Framework>

<Framework when="nuxt">

**`useConsentActions is not defined`.**
`@cookieyes/nuxt` is missing from `modules` in `nuxt.config.ts`. See [Installation](/docs/getting-started/installation).

</Framework>
