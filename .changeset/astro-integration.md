"@cookieyes/astro": minor
---

Astro 6 and 7 sites can now add the CookieYes consent banner with one integration, and a static page decides before first paint whether to show it, so a returning visitor never sees it flash.

**New: `@cookieyes/astro`.** Run `npx astro add @cookieyes/astro` (or add `cookieyes()` to `integrations`) and put `<CookieYesRoot />` from `@cookieyes/astro/components` in your layout. The options are the same as `initCookieYes` everywhere else. Options that hold functions, such as integrations and callbacks, go in `src/cookieyes.client.ts`, which is found automatically; a function left in `astro.config.mjs` gets a warning in development. There is no CSS to import, and `networkBlocker` rules work without a `registerNetworkBlocker()` call. `CookieBanner`, `CookiePreferences`, `CookieOptOut`, `RecallButton`, `ReloadNotice`, `GatedScript` and `GatedFrame` are available for a custom set, with `class` and `classNames`. `@cookieyes/astro/client` has `getConsent`, `getConsentCategory`, `getConsentActions`, `onConsentChange`, `openPreferences`, `openOptOut` and `getCookieYes`, which wait for the runtime, so they work from an island that loads first, plus `registerStopHandler` and `blockIframes` as in the other adapters. `youTubeEmbedUrl` is exported from `@cookieyes/astro/components`.

**Static and on-request pages.** On a prerendered page the banner is in the HTML, hidden, and a small inline script reads the consent cookie before first paint with core's own parser: a first-time visitor sees the banner at once, a returning visitor never does, and no request is made. On a page rendered on request the integration reads the consent cookie, the Vercel and Cloudflare geo headers and `Sec-GPC`, as `@cookieyes/nextjs` does, into a typed `Astro.locals.cookieyes`, so a visitor who already chose gets no banner markup and a California visitor gets the CCPA banner from the first byte. `getServerConsent(Astro)` and `getServerRegion(Astro)` are in `@cookieyes/astro/server`. With `<ClientRouter />` the banner, open dialogs and the recall button survive navigation, and gated scripts and frames on the new page follow current consent.

**Styles and CSP.** The critical CSS is inlined after `<meta charset>` (`CRITICAL_CSS_HASH` has the same value as in the other adapters), the full stylesheet is served from `/cookieyes/styles.css`, and with `googleConsentMode` Google Consent Mode's deny-by-default goes at the top of `<head>`, before any Google tag. With Astro's `security.csp` on, the hashes of these inline tags are added to the policy for you; for a policy you set yourself, `astro build` prints them.
